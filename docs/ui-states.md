# UI 상태 점검 결과 (AGENT_TASK 7)

2026-10-20, 시뮬레이터 사이드카 + headless Edge(DevTools 프로토콜로 실시간 제어)로 각 상황을 실제로 만들어 확인했다.
상태 처리는 공통 부품(`web/src/components/Panel.tsx`, `Layout.tsx`, `lib/usePolling.ts`, `lib/connection.ts`)에 있어 모든 화면에 같이 적용된다.

색만으로 구분하지 않도록 모든 상태에 아이콘(✓ ● ▲ ✕ ⊖ ○)과 문구를 함께 썼다.

## 시험 도구

- 장애 주입: 시뮬레이터 전용 `MSDASH_SIM_FAULT_FILE`. 파일에 `collector_down` 또는 `worker_timeout:<idx>`를 줄마다 적는다. 실제 수집(hook)에는 영향이 없다.
- 시험용 프록시·DevTools 스크립트는 작업 디렉터리 밖(임시 폴더)에 두었다. 저장소에는 넣지 않았다.

## 확인하며 고친 것

- 첫 로딩 스켈레톤을 카드 모양으로 바꿈 (막대만 있던 것)
- 서버 연결이 끊긴 동안 상단 띠가 "수집 정상"(초록)으로 남던 것 → "서버 응답 없음 · 마지막으로 받은 값"
- 방송이 없을 때 pipe 상태가 경고(▲ 데이터 없음)로 보이던 것 → 중립 "⊖ pipe 없음"
- 24시간 이력이 비었을 때 "현재 울리는 알림 없음"으로 나오던 문구
- 로딩 중 사이드바에 "Origin 대시보드 (주소 없음)"이 보이던 것
- `MSDASH_SIM_ROOMS=0`이 기본값(3)으로 바뀌던 설정 해석

## 참고

- 사이드카 재시작 직후 첫 수집 구간은 누적값의 기준이 없어 "값 없음"이 된다 (AGENT_TASK 4.2-2). 차트에서는 선이 한 칸 끊긴다.
- headless 브라우저는 창 너비를 492px 아래로 줄일 수 없어 휴대폰 너비(390px)는 직접 확인하지 못했다. 600px에서는 가로 넘침 없이 표시된다.
